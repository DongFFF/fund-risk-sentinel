## 一、模型 API 接入

### 1.1 配置文件

`config/providers.yaml`（**已被 .gitignore 排除，不会上传**；模板见 `config/providers.example.yaml`）：

```yaml
active: deepseek          # 当前激活的 provider
fallback: [qwen, mock]    # 主 provider 失败时依次尝试

providers:

  deepseek:
    type: openai_compatible
    base_url: https://api.deepseek.com/v1
    api_key: ${DEEPSEEK_API_KEY}     # 支持 ${ENV_VAR} 与 ${VAR:-默认值}
    model: deepseek-chat
    temperature: 0.1
    max_tokens: 4096
    timeout: 120
    max_retries: 2
    adaptation_path: prompt          # 标注该 provider 对应的适配路径
    cost_per_1k_prompt: 0.001        # 用于估算成本（元/千 token）
    cost_per_1k_completion: 0.002
```

### 1.2 支持的服务类型

| `type` | 覆盖服务 |
| --- | --- |
| `openai_compatible` | DeepSeek、通义千问、Kimi、智谱、OpenAI、Ollama、vLLM、LM Studio、任何 `/chat/completions` 端点 |
| `anthropic` | Claude 系列 |
| `gemini` | Google Gemini |
| `mock` | 内置离线模拟，用于无网络自检与降级兜底 |
| `custom` | 未注册时按 OpenAI 兼容处理；也可自行继承 `BaseLLMProvider` 后注册 |

### 1.3 各厂商配置速查

```yaml
# DeepSeek
deepseek:
  type: openai_compatible
  base_url: https://api.deepseek.com/v1
  api_key: ${DEEPSEEK_API_KEY}

# Kimi（月之暗面）

# 智谱 GLM
zhipu:
  type: openai_compatible
  base_url: https://open.bigmodel.cn/api/paas/v4
  api_key: ${ZHIPU_API_KEY}

# 本地 Ollama（完全离线，材料不出本机）

  type: openai_compatible
  base_url: http://127.0.0.1:11434/v1
  api_key: EMPTY
```

### 1.4 环境变量插值

```yaml
api_key: ${DEEPSEEK_API_KEY}              # 未设置则为空字符串
base_url: ${LLM_BASE:-http://127.0.0.1:8000/v1}   # 未设置则用默认值
```

推荐把 Key 放系统环境变量，而不是写进配置文件。

### 1.5 错误处理

| HTTP 状态 | 处理 |
| --- | --- |
| 401 / 403 | 抛 `LLMAuthError`，提示检查 API Key |
| 404 | 抛 `LLMError`，提示检查 `base_url` 是否含 `/v1` |
| 429 | 抛 `LLMRateLimitError` |
| 5xx / 网络错误 | 指数退避重试 `min(2^(n-1), 8.0)` 秒 |
| 本地连接失败 | 附加提示"Ollama/vLLM 是否已启动" |

## 二、材料上传接口

全部返回统一的 `IngestResult`：

```python
@dataclass
class IngestResult:
    items: list[IngestItem]        # 逐份材料的处理结果（含失败原因）
    materials: list[Material]      # 成功解析的材料
    warnings: list[str]            # 非致命提示
    def summary(self) -> str: ...  # 一句话汇总
```

### 2.1 Python 调用

```python
from fund_risk_sentinel import IngestPipeline
from fund_risk_sentinel.core.enums import DocumentRole

pipe = IngestPipeline()

# ① 从文件路径
result = pipe.load_paths(["报销单.docx", "发票.pdf"])

# ② 从文件夹（自动过滤不支持的扩展名）
result = pipe.load_folder("D:/待审材料")

# ③ 从内存字节流（浏览器上传 / 接口调用）
with open("报销单.docx", "rb") as fh:
    result = pipe.load_bytes("报销单.docx", fh.read())

# ④ 手工粘贴文本
result = pipe.load_text("报销人：张伟\n金额：9560", name="临时核对.txt")

# 指定角色（跳过自动判定）
result = pipe.load_paths(["校内细则.pdf"], role_overrides={"校内细则.pdf": DocumentRole.POLICY})

# 装配成送模型的上下文（制度优先排序 + 预算截断 + 诚实标注）
context, warnings = pipe.assemble_context(result.materials)
```

### 2.2 支持格式

| 扩展名 | 解析器 | 说明 |
| --- | --- | --- |
| `.txt` | TextLoader | 多编码自动探测 |
| `.md` / `.markdown` | MarkdownLoader | 抽取标题层级 |
| `.csv` | CsvLoader | Sniffer 自动判分隔符 |
| `.json` | JsonLoader | `list[dict]` 自动转表格 |
| `.docx` | DocxLoader | 按文档流遍历段落与表格；`.doc` 需先转格式 |
| `.xlsx` | XlsxLoader | read_only + data_only，最多 20 个工作表 |
| `.pdf` | PdfLoader | pypdf → PyMuPDF → OCR 三级；加密文件明确报错 |
| `.png/.jpg/.jpeg/.bmp/.tiff/.webp` | ImageLoader | OCR 或多模态；都不可用时打 `needs_ocr` 标 |

### 2.3 材料角色（`DocumentRole`）

自动判定规则（`ingest/roles.py`）：

1. **结构判据优先**：行首匹配「第X条」≥ 3 处 → 直接判 `POLICY`
2. **关键词打分**：文件名权重 3.0，内容权重 1.0，阈值 2.0

| 角色 | 标签 | 典型材料 |
| --- | --- | --- |
| `POLICY` | 制度文本 | 管理办法、实施细则、负面清单 |
| `APPLICATION` | 申请/报销单 | 报销单、借款单、预算申请表 |
| `CONTRACT` | 合同/协议 | 技术服务合同、采购合同 |
| `INVOICE` | 发票/票据 | 增值税发票、收据 |
| `APPROVAL` | 审批意见 | 审批单、签批记录 |
| `ACCEPTANCE` | 验收材料 | 验收单、成果交付确认 |
| `BUDGET` | 预算材料 | 预算表、预算执行表 |
| `OTHER` | 其他 | 未识别 |

**结构判据优先的原因**：文件名含"报销"的校内实施细则，若只按关键词判会被误判为报销单。条文结构是最可靠的角色信号。

## 三、规则库格式

规则文件放在 `config/rules/` 下，YAML 格式。加载顺序：`builtin/` → `institution/`，**同 ID 后者覆盖前者**（校内细则可覆盖内置规则）。

```yaml
version: "1.0"
source: builtin           # builtin / institution / custom
dimension: amount         # 文件级默认维度，规则可单独覆盖
tags: [额度, 预算]

rules:

  - id: AMT-001                     # 规则 ID（唯一，被引用与排查时使用）
    name: 支出超出预算科目余额
    event_types: [reimbursement, advance, procurement]
    condition: 'budget_amount > 0 and amount > budget_amount'
    requirement: 各项支出应当在批复的预算科目额度内列支。
    risk_category: deviation        # missing/conflict/deviation/override/anomaly
    level_hint: high                # unknown/low/medium/high
    disposition_hint: restrict      # 见下方处置类型
    suggestion: 请核对预算科目余额，确认是否需要办理预算调整。
    basis:                          # 制度依据
      - doc_title: 中央高校基本科研业务费管理办法
        doc_no: 财教〔2021〕177 号
        text: 项目负责人应当按照批复的预算科目和额度使用经费。
```

### 3.1 条件表达式可用变量

由 `build_facts()` 提供：

| 变量 | 类型 | 说明 |
| --- | --- | --- |
| `amount` | float | 本笔金额 |
| `budget_amount` | float | 预算科目余额 |
| `contract_amount` | float | 合同金额 |
| `budget_subject` | str | 经费科目 |
| `purpose` | str | 用途/事由 |
| `event_type` | str | 事项类型 |
| `days_after_event` | int | 业务发生至办理的天数（自动推算） |
| `has_contract` / `has_invoice` / `has_approval` / `has_acceptance` | bool | 附件齐全性 |
| `invoice_count` | int | 发票份数 |
| `material_count` | int | 材料份数 |
| `missing_attachments` | list | 缺失附件清单 |
| `approver_level` | str | 审批层级 |
| `supplier` | str | 供应商 |
| `project_name` / `project_code` | str | 项目名称/编号 |
| `applicant` / `approver` | str | 经办人 / 审批人 |
| `text` | str | 全部材料拼接文本 |
| `fields` | dict | 原始抽取字段（`fields.get("x")`） |

### 3.2 可用函数

`abs` `min` `max` `len` `round` `int` `float` `str` `bool` `sum` `any` `all`
`to_number(x)` `is_empty(x)` `contains_any(text, *words)` `contains_all(text, *words)`
`regex_match(text, pattern)` `days_between(d1, d2)`

### 3.3 安全边界

条件表达式在 **AST 白名单沙箱**中求值，禁止：`__import__`、属性穿透、列表推导、lambda、文件访问。
原因：规则文件可被校内自行编辑，用 `eval` 等于开放任意代码执行。

### 3.4 处置类型（`disposition_hint`）

`supplement`（补充材料） · `return`（退回） · `restrict`（限制） · `consult`（会商） ·
`adjust_budget`（调整预算） · `release_recorded`（放行留痕） · `pending_review`（待复核）

## 四、制度知识库格式

支持两种来源，放在 `config/knowledge/` 下。

### 4.1 YAML（结构化条款）

```yaml
doc_title: 国家自然科学基金资助项目资金管理办法
doc_no: 财教〔2021〕177 号
effective_date: "2021-09-30"
clauses:
  - article: 第十二条
    text: 直接费用中，设备费、材料费、测试化验加工费……应当据实列支。
    tags: [额度, 用途]
  - article: 第十三条
    text: 劳务费开支范围包括项目组成员中没有工资性收入的相关人员。
    tags: [用途, 人员]
```

### 4.2 Markdown（按「第X条」自动切分）

```markdown
# 某高校科研经费报销实施细则

## 第一章 总则

第一条 为规范科研经费报销，根据国家有关规定，制定本细则。

第二条 本办法适用于以学校名义取得的各类科研经费。
```

加载时自动按「第X条」切分为独立条款，文件标题作为 `doc_title`。

### 4.3 检索

```python
from fund_risk_sentinel.rules import load_knowledge_base

kb = load_knowledge_base("config/knowledge")
refs = kb.search("差旅费超标准报销", top_k=6)
for ref in refs:
    print(ref.doc_title, ref.article, ref.text[:50])

# 供提示词注入
block = kb.format_for_prompt(refs)
```

## 五、Python API（脱离界面使用）

```python
from fund_risk_sentinel import (
    ReviewPipeline, PipelineOptions, EventType, render_markdown,
)

pipeline = ReviewPipeline.from_config()          # 读 config/settings.yaml + providers.yaml

options = PipelineOptions(
    event_type=EventType.REIMBURSEMENT,
    provider="deepseek",        # 不填则用配置里的 active
    enable_rules=True,
    enable_rag=True,
    enable_llm=True,
)

# 方式一：直接给文件路径
conclusion = pipeline.run_paths(
    ["报销单.docx", "发票.pdf", "预算执行表.xlsx"],
    title="2026年3月差旅报销审查",
    options=options,
)

# 方式二：给已解析的材料
result = pipeline.ingest.load_paths([...])
conclusion = pipeline.run_materials(result.materials, options=options)

# 方式三：给完整任务对象（结论会写回 task）
task = ReviewTask(title="...", event_type=EventType.REIMBURSEMENT, materials=result.materials)
conclusion = pipeline.run_task(task, options=options)

# 输出
print(conclusion.summary)
for f in conclusion.findings:
    print(f.level, f.title, f.rationale)
print(render_markdown(conclusion))               # 完整 Markdown 底稿
```

### 阶段回调（用于进度展示）

```python
def on_stage(record):
    print(f"[{record.status}] {record.title} —— {record.message}")

options = PipelineOptions(on_stage=on_stage)
```

## 六、配置项参考

`config/settings.yaml`：

```yaml
app_name: 高校科研经费风险智能识别系统
data_dir: ""            # 留空用 %LOCALAPPDATA%/FundRiskSentinel
db_path: ""             # 留空用 <data_dir>/sentinel.db
rules_dir: ""           # 留空用 <项目>/config/rules
knowledge_dir: ""       # 留空用 <项目>/config/knowledge

ui:
  theme: light
  page_size: 50
  font_size: 10

review:
  enable_rule_engine: true
  enable_rag: true
  enable_llm_reasoning: true
  degrade_on_llm_failure: true        # 模型挂了退回规则结果并明确标注
  max_chars_per_material: 20000
  total_prompt_char_budget: 60000
  max_findings: 50
  min_confidence: 0.35                # 低于该置信度的线索不输出

security:
  redact_id_card: true
  redact_phone: true
  redact_bank_account: true
  redact_email: true
  redact_person_name: false           # 默认关闭，会显著影响可读性
  retention_days: 1825                # 材料与结论保存期限（天）
  audit_log_enabled: true
  data_classification: 内部
  allow_cloud_providers: true         # 关闭后只允许本地模型
  mask_api_key_in_ui: true
```
