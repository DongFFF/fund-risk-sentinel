> 本文说明"怎么知道这套系统好不好用"。对应课题表2 的六维指标，实现在 `evaluate/metrics.py`。

---

## 一、为什么是这六个维度

单一指标无法描述这类系统的质量：

- 只看**准确率** → 系统可以少报来刷高分（只报最有把握的几条）
- 只看**召回率** → 系统可以滥报来刷高分（把什么都标成风险）
- 不看**时延** → 结果再准，审核人等到放弃也没用
- 不看**一致性** → 同一份材料两次结果不同，无法建立信任
- 不看**可解释性** → 审核人无法判断线索是否成立，只能盲从或无视
- 不看**采纳度** → 前五项都可以好，但审核人就是不认，系统等于没上

因此必须**同时**看六个维度，且刻意让"可解释性"与"采纳度"起到抑制"滥报"的作用。

---

## 二、六维定义与阈值

| 维度 | 含义 | 口径 | 阈值 | 目标取向 |
| --- | --- | --- | --- | --- |
| **准确性** `accuracy` | 报出的线索中有多少站得住 | （采纳 + 0.5 × 部分采纳）/ 已复核数 | ≥ 0.80 | 持续提升 |
| **召回性** `recall` | 该发现的有没有发现 | 采纳数 /（采纳数 + 漏报数） | ≥ 0.70 | 持续提升 |
| **时延** `latency` | 一次审查要等多久 | 各结论 `duration_ms` 的均值与 P95 | 均值 ≤ 60000 ms | 满足业务时效 |
| **一致性** `consistency` | 同一输入结果是否稳定 | 重复回放结果的 Jaccard 相似度 | ≥ 0.85 | 保持稳定 |
| **可解释性** `explainability` | 每条线索能否追溯 | 带证据定位 + 带依据的线索占比 | ≥ 0.90 | 完整可追溯 |
| **审核采纳度** `adoption` | 审核人实际采纳比例 | 采纳数 / 已复核数 | ≥ 0.60 | 稳步提高 |

阈值定义在 `DEFAULT_THRESHOLDS`，可按学校实际情况覆盖：

```python
from fund_risk_sentinel.evaluate import Evaluator
from fund_risk_sentinel.core.enums import MetricDimension

evaluator = Evaluator(
    repository=repo,
    thresholds={MetricDimension.RECALL: 0.75},   # 只覆盖需要调整的维度
)
```

## 三、各维度的计算细节

### 3.1 准确性 —— 部分采纳算半分

```
准确性 = (采纳数 + 0.5 × 部分采纳数) / 已复核数
```

**为什么部分采纳算 0.5？** 审核人的"部分采纳"通常意味着"方向对、程度或表述有偏差"。算 1 分高估了系统，算 0 分低估了它。

**分母只算"已复核"**：未复核的线索不计入分母，也不计入分子。没有人工基准就不该给分数。

### 3.2 召回性 —— 依赖"漏报"标注

```
召回性 = 采纳数 / (采纳数 + 漏报数)
```

`HumanVerdict.MISSED` 表示"人工补充的新线索（模型漏报）"。这个标签需要审核人在复核时主动补录——**这是全系统唯一依赖人工额外投入的环节**，也是召回率数据前期偏乐观的原因。

### 3.3 时延 —— 看均值也看长尾

- 均值反映日常体验
- P95 反映"最坏情况有多坏"——审核人往往更在意后者

`_percentile` 用最近秩法（nearest-rank），实现简单、结果可复现。

### 3.4 一致性 —— Jaccard 相似度

对同一批材料连续跑两次，比较两次结果集合的 Jaccard 相似度：

```
J(A, B) = |A ∩ B| / |A ∪ B|
```

集合元素用线索标题归一化后匹配。相似度越高说明结果越稳定。

**一致性低通常来自两个原因**：温度参数过高，或提示词里存在让模型"自由发挥"的空间。前者调 `temperature`，后者收紧 `prompts/`。

### 3.5 可解释性 —— 证据定位覆盖率

```
可解释性 = 同时具备(证据定位 且 制度依据)的线索数 / 总线索数
```

**为什么阈值定到 0.90？** 因为它同时起到抑制滥报的作用：随口报一条没有证据的线索，会拉低这个指标。想报就得出示依据。

### 3.6 采纳度 —— 最终的"人是否认账"

```
采纳度 = 采纳数 / 已复核数
```

这是唯一一个"系统自己说了不算"的指标。

## 四、样本量与诚实披露

```python
_MIN_SAMPLE = 5
```

系统**不会**在小样本下给出漂亮分数然后闭口不谈：

| 情况 | 系统行为 |
| --- | --- |
| 无任何线索记录 | 指标留空 + 提示"请先完成至少一次审查任务" |
| 线索数 < 5 | 照常计算，但附注"样本量偏小，仅供趋势参考" |
| 有未复核线索 | 附注"有 N 条尚未复核，未复核部分不计入分母" |

**为什么强调这一点？** 在尚无标准化标注数据的阶段，最容易犯的错误就是"拿几条样本跑出个高准确率然后写进报告"。宁可标注"数据不足"，也不输出误导性结论。

## 五、使用方法

### 5.1 界面

「能力评测」页：

1. 点「计算指标」→ 从数据库取全部线索与结论，算六维
2. 点「一致性回放」→ 对最近任务连续跑两次，比较 Jaccard
3. 点「导出报告」→ 生成 Markdown

### 5.2 Python

```python
from fund_risk_sentinel import Evaluator, format_report

evaluator = Evaluator(repository=repo)

# 全量评测
report = evaluator.evaluate()
print(format_report(report))

# 指定任务
report = evaluator.evaluate(task_ids=["task_xxx"])

# 直接传数据（离线测试）
report = evaluator.evaluate(findings=findings, conclusions=conclusions)

# 提供回放结果才能算真实一致性
report = evaluator.evaluate(replays=[run1_findings, run2_findings])
```

### 5.3 一致性回放怎么做

```python
from fund_risk_sentinel import ReviewPipeline, PipelineOptions

pipeline = ReviewPipeline.from_config()
opts = PipelineOptions(event_type=EventType.REIMBURSEMENT)

run1 = pipeline.run_paths(paths, options=opts)
run2 = pipeline.run_paths(paths, options=opts)

report = Evaluator(repository=repo).evaluate(
    findings=run1.findings,
    conclusions=[run1],
    replays=[run1.findings, run2.findings],
)
```

## 六、指标与治理的联动

六维不是各自独立的评分，而是**互相制约**：

```
             滥报（宁滥勿缺）             漏报（宁缺勿滥）
                   │                          │
                   ▼                          ▼
            可解释性 ↓                    召回性 ↓
            采纳度   ↓                    准确性 ↑（假象）
                   │                          │
                   └────────┬─────────────────┘
                            ▼
                  必须在两者间找平衡点
```

- 可解释性阈值 0.90 + 采纳度阈值 0.60 共同**惩罚滥报**
- 召回性阈值 0.70 **惩罚漏报**
- 想同时达标，只能靠"报得准"而不是"报得多"或"报得少"
